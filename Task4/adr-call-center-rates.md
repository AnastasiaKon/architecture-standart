# Task4. ADR: Передача актуальных ставок в кол-центр и партнёрский кол-центр

## Статус

Accepted for MVP.

## Контекст

Банк «Стандарт» планирует цифровизировать процесс открытия депозитов и накопительных счетов.  
В рамках MVP клиенты смогут подавать заявки на депозит через сайт и интернет-банк, а сотрудники бэк-офиса продолжат обрабатывать заявки по текущему процессу.

Дополнительно появилась новая проблема: после запуска маркетинговой кампании количество звонков в кол-центр может резко вырасти. Основная клиентская база банка — люди старшего возраста, которым может быть сложно самостоятельно разобраться в новых онлайн-процессах. Поэтому операторы должны иметь возможность быстро и корректно консультировать клиентов по актуальным ставкам депозитов.

Нужно обеспечить:

- доступ сотрудников внутреннего кол-центра к актуальным депозитным ставкам;
- передачу актуальных ставок в партнёрский кол-центр;
- минимизацию ручной передачи Excel-файлов;
- контролируемое обновление ставок;
- возможность использовать решение в MVP и развивать его в целевой архитектуре.

Важное ограничение: партнёрский кол-центр работает во внешней системе и не может вызывать API банка. Он готов получать актуальные ставки в виде файлов через SFTP.

## Проблема

Сейчас ставки депозитов рассчитываются и передаются в Excel-файлах. Такой процесс плохо подходит для масштабирования консультаций:

- ставки могут устаревать;
- невозможно гарантировать, что оператор использует последнюю версию;
- сложно обеспечить аудит изменений;
- невозможно автоматически передать данные партнёрскому кол-центру;
- ручная отправка файлов создаёт операционные риски;
- при высокой нагрузке возрастает риск ошибок в консультациях.

## Use Cases

### UC1. Оператор внутреннего кол-центра консультирует клиента по депозитам

**Участники:** клиент, оператор кол-центра, система кол-центра, Deposit Rates Service.

1. Клиент звонит в кол-центр.
2. Оператор открывает карточку консультации в системе кол-центра.
3. Система кол-центра показывает актуальные депозитные продукты и ставки.
4. Оператор консультирует клиента.
5. Если клиент заинтересован, оператор создаёт обращение или заявку по текущему процессу.

### UC2. Партнёрский кол-центр получает актуальные ставки файлом

**Участники:** Rate Export Service, SFTP-сервер, партнёрский кол-центр.

1. Deposit Rates Service хранит актуальные ставки.
2. Rate Export Service формирует файл со ставками в согласованном формате.
3. Файл публикуется на SFTP-сервере банка или отправляется на SFTP партнёра.
4. Партнёрский кол-центр загружает файл.
5. Операторы партнёра консультируют клиентов по актуальным ставкам.

### UC3. Сотрудник бэк-офиса обновляет ставки

**Участники:** бэк-офис депозитов, бэк-офис кредитов, Deposit Rates Service.

1. Сотрудник бэк-офиса депозитов обновляет базовые ставки.
2. При необходимости учитываются параметры кредитного риска и специальные условия.
3. Deposit Rates Service сохраняет новую версию ставок.
4. Внутренний кол-центр получает обновление через API или синхронизацию.
5. Rate Export Service формирует новый файл для партнёрского кол-центра.

### UC4. Обнаружена ошибка в файле ставок

**Участники:** команда эксплуатации, Rate Export Service, партнёрский кол-центр.

1. Мониторинг или сотрудник обнаруживает ошибку формирования файла.
2. Ошибка фиксируется в логах и алертах.
3. Ответственный сотрудник повторно запускает экспорт или откатывает версию ставок.
4. Партнёрский кол-центр получает корректный файл.
5. Инцидент фиксируется для аудита.

## Функциональные требования

- Внутренний кол-центр должен видеть актуальные депозитные ставки.
- Система кол-центра должна получать ставки из управляемого источника, а не из Excel по почте.
- Партнёрский кол-центр должен получать ставки файлом через SFTP.
- Файл для партнёрского кол-центра должен содержать только данные, необходимые для консультации: название продукта, срок, валюта, ставка, условия, дата начала действия.
- Файл не должен содержать персональные данные клиентов.
- Каждая версия ставок должна иметь дату и время действия.
- Должна храниться история изменений ставок.
- Должна быть возможность повторно сформировать файл за выбранную версию ставок.
- Должна быть возможность проверить, какая версия ставок была передана партнёру.
- Должны быть логи успешной и неуспешной передачи файла.

## Нефункциональные требования

- Данные о ставках должны быть актуальны для внутреннего кол-центра в течение нескольких минут после публикации.
- Файл для партнёрского кол-центра должен формироваться по расписанию и при изменении ставок.
- Передача файла должна выполняться по защищённому каналу SFTP.
- Доступ к SFTP должен быть ограничен техническими учётными записями и ключами.
- Решение не должно создавать прямую нагрузку на АБС.
- Решение должно использовать Deposit Rates Service как единый источник ставок.
- Ошибки экспорта должны попадать в мониторинг и алерты.
- Должна быть возможность ручного повторного запуска экспорта.
- Формат файла должен быть документирован и согласован с партнёром.
- Решение должно быть совместимо с будущей автоматизацией открытия депозитов.

## Решение

Выбираем архитектуру, в которой **Deposit Rates Service** становится единым источником актуальных ставок для онлайн-каналов, внутреннего кол-центра и партнёрского кол-центра.

Для внутреннего кол-центра используется интеграция через API или синхронизационный адаптер:

- система кол-центра получает ставки из Deposit Rates Service;
- для снижения зависимости можно использовать локальный кеш ставок в системе кол-центра;
- оператор видит ставки в интерфейсе кол-центра.

Для партнёрского кол-центра создаётся отдельный **Rate Export Service**:

- получает актуальные ставки из Deposit Rates Service;
- формирует файл в согласованном формате, например CSV или XLSX;
- публикует файл через SFTP;
- пишет журнал экспорта;
- поддерживает повторный запуск экспорта;
- не передаёт персональные данные.

## Компоненты решения

### Deposit Rates Service

Единый источник депозитных продуктов и ставок.

Ответственность:

- хранение актуальных ставок;
- версионирование ставок;
- аудит изменений;
- API для онлайн-каналов и внутреннего кол-центра;
- предоставление данных для Rate Export Service.

### Deposit Rates DB

База данных ставок.

Хранит:

- депозитные продукты;
- параметры ставок;
- версии ставок;
- сроки действия;
- историю изменений;
- автора изменений.

### Call Center Rates Adapter

Интеграционный компонент для внутренней системы кол-центра.

Ответственность:

- получение ставок из Deposit Rates Service;
- преобразование формата под систему кол-центра;
- кеширование ставок;
- обработка ошибок интеграции.

### Internal Call Center System

Существующая система кол-центра банка.

В MVP получает возможность показывать операторам актуальные ставки депозитов.

### Rate Export Service

Компонент экспорта ставок для партнёрского кол-центра.

Ответственность:

- формирование файла ставок;
- валидация файла;
- публикация файла через SFTP;
- хранение статуса экспорта;
- повторный запуск экспорта;
- логирование и мониторинг.

### SFTP Server

Защищённый канал передачи файла партнёрскому кол-центру.

Возможны два варианта:

- SFTP-сервер на стороне банка, партнёр забирает файл;
- SFTP-сервер на стороне партнёра, банк загружает файл.

Для MVP предпочтительнее SFTP-сервер банка, потому что банк лучше контролирует публикацию, аудит и права доступа.

### Partner Call Center System

Внешняя система партнёрского кол-центра.

Не вызывает API банка. Получает файл со ставками через SFTP и использует его для консультаций.

## Альтернативы

### Альтернатива 1. Продолжать отправлять Excel-файлы по email

Плюсы:

- минимальные изменения;
- сотрудники уже привыкли к процессу;
- быстро запустить.

Минусы:

- высокий риск устаревших ставок;
- нет нормального аудита;
- сложно контролировать, какая версия используется;
- высокая вероятность ручных ошибок;
- плохо масштабируется при росте звонков;
- небезопасный способ передачи данных.

Решение отклонено.

### Альтернатива 2. Дать внутреннему и партнёрскому кол-центру прямой доступ к АБС

Плюсы:

- данные берутся из core-системы;
- меньше промежуточных компонентов.

Минусы:

- АБС уже перегружена;
- АБС масштабируется только вертикально;
- партнёрский кол-центр не должен получать прямой доступ к банковской системе;
- возникают серьёзные риски безопасности;
- сложнее контролировать внешние обращения.

Решение отклонено.

### Альтернатива 3. Сделать API для партнёрского кол-центра

Плюсы:

- данные можно получать в реальном времени;
- не нужен файловый обмен.

Минусы:

- партнёрский кол-центр не готов вызывать API;
- потребуется больше согласований по безопасности;
- увеличивается срок MVP;
- интеграция будет зависеть от внешней системы партнёра.

Решение отклонено для MVP. Может быть рассмотрено позже, если партнёр изменит технические возможности.

### Альтернатива 4. Загружать ставки вручную в систему кол-центра

Плюсы:

- проще, чем API-интеграция;
- можно сделать быстро.

Минусы:

- ручной процесс;
- риск ошибок загрузки;
- нет автоматической синхронизации;
- плохо подходит для частых изменений ставок;
- не решает проблему партнёрского кол-центра.

Решение отклонено.

## Недостатки выбранного решения

- Появляется новый компонент Rate Export Service, который нужно разрабатывать и сопровождать.
- Нужно согласовать формат файла с партнёрским кол-центром.
- Нужно настроить и сопровождать SFTP-инфраструктуру.
- При файловом обмене данные у партнёра не полностью real-time.
- Нужно контролировать, что партнёр использует последнюю версию файла.
- Для внутреннего кол-центра потребуется доработка системы подрядчика или расширение через адаптер.

## Последствия

Положительные последствия:

- операторы получают актуальные ставки;
- партнёрский кол-центр может быть подключён к консультациям;
- снижается ручная передача Excel-файлов;
- появляется аудит версий ставок;
- решение не нагружает АБС;
- Deposit Rates Service становится единым источником ставок;
- архитектура готова к развитию онлайн-депозитов и кредитных продуктов.

Негативные последствия:

- увеличивается количество компонентов;
- появляется необходимость мониторинга экспорта;
- нужно управлять доступами к SFTP;
- нужно согласовать операционный процесс с партнёром;
- нужно обучить операторов работе с обновлёнными ставками.

## Крупные задачи для планирования

### Deposit Rates Service

- Реализовать модель депозитных продуктов и ставок.
- Добавить версионирование ставок.
- Добавить аудит изменений.
- Реализовать API получения актуальных ставок.
- Реализовать API получения версии ставок по дате.
- Подготовить документацию API.

### Система внутреннего кол-центра

- Добавить экран/блок просмотра депозитных ставок.
- Реализовать интеграцию с Call Center Rates Adapter.
- Добавить кеш ставок для устойчивости при временной недоступности Deposit Rates Service.
- Добавить отображение даты актуальности ставок.
- Обновить скрипты консультаций.

### Call Center Rates Adapter

- Реализовать получение ставок из Deposit Rates Service.
- Реализовать преобразование формата данных.
- Реализовать кеширование.
- Реализовать обработку ошибок.
- Добавить технические логи и метрики.

### Rate Export Service

- Согласовать формат файла ставок.
- Реализовать генерацию CSV/XLSX.
- Реализовать валидацию файла перед отправкой.
- Реализовать публикацию файла через SFTP.
- Реализовать расписание экспорта.
- Реализовать экспорт по событию изменения ставок.
- Реализовать повторный запуск экспорта.
- Реализовать журнал экспортов.

### SFTP-инфраструктура

- Поднять SFTP-сервер банка или настроить подключение к SFTP партнёра.
- Создать технические учётные записи.
- Настроить ключи доступа.
- Настроить ротацию ключей.
- Настроить аудит скачивания или загрузки файлов.
- Настроить мониторинг доступности SFTP.

### Партнёрский кол-центр

- Согласовать формат файла.
- Согласовать расписание получения файла.
- Настроить загрузку файла в процесс консультаций.
- Обновить скрипты операторов.
- Провести тестовую выгрузку и приёмку.

### Эксплуатация и безопасность

- Настроить мониторинг ошибок экспорта.
- Настроить алерты по просроченному файлу ставок.
- Настроить алерты по недоступности SFTP.
- Подготовить инструкцию ручного повторного экспорта.
- Подготовить регламент проверки актуальности ставок.
- Провести проверку, что файл не содержит персональных данных.
